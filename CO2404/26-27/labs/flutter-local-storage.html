Introduction

As with any project, the right tooling is vital and getting these tools to work for you takes time to master. In this lab you will build a mobile application that stores data locally on the device.

Storing data locally provides an effective user experience. If there is no valid connection, the user should still be able to use your application to some extent. If the connection is slow, you can retrieve information faster because it is stored on the device rather than in the cloud. It also lets you personalise the experience: settings, modes and preferences that make an application accessible, configurable and functional for each user.

In the lecture we looked at the options available in Flutter:

SharedPreferences uses the default mechanisms of each platform (NSUserDefaults on iOS and SharedPreferences on Android). SQLite is a small, fast, self-contained database engine that is built into every mobile device. It is similar to MySQL in that you interface with the data using similar queries and operations, and like MySQL it is a relational database. This is different to Firebase, which you will learn about later in the module.

Note

With Firebase you are creating a storage option in the cloud. Although Firebase can handle offline persistence (when enabled) by queuing data for when a connection is available, you are expected to build your own local database to demonstrate that you understand how to read, write, update and delete data.

In this lab you will build a Data Notebook application that:

  • Asks the user to choose a light or dark mode and remembers the choice using SharedPreferences.

  • Stores a list of items in an SQLite database.

  • Displays the list dynamically from the database.

  • Lets the user create, read, update and delete items.

Each activity builds upon the previous one.

    1.5 Detect the Platform

    The platform package gives a cross-platform way to ask where the app is running. On a native platform, Platform.current.nativePlatform holds the familiar dart:io properties. In the browser it is null, and Platform.current.browserPlatform is used instead.

    Create lib/database/platform_info.dart:

    x
    import 'package:platform/platform.dart';
    

    String describePlatform() {
      switch (Platform.current) {
        case Platform(:var nativePlatform?):
          // `nativePlatform` has `dart:io`'s `Platform` properties.
          return 'Running on ${nativePlatform.operatingSystem} v.'
              '${nativePlatform.operatingSystemVersion}';
        case Platform(:var browserPlatform?):
          // `browserPlatform` has version information from `window.navigator.userAgent`.
          return 'Running on ${browserPlatform.userAgent}';
        default:
          return 'Running on an unknown platform';
      }
    }

    We will print this when the app starts, so you always know which database factory you are testing.

    1.6 Choose the Database Factory

    Knowing the platform at run time is not enough.     x

      throw UnsupportedError('This platform is not supported.');

    Create lib/database/platform_setup_web.dart:

    x
    

    import 'package:sqflite_common_ffi_web/sqflite_ffi_web.dart';
    

    Future<void> initDatabaseFactory() async {
      // Use the WebAssembly version of SQLite (saved in IndexedDB)
      databaseFactory = databaseFactoryFfiWeb;
    }

    Create lib/database/platform_setup_io.dart:

    x
    import 'package:platform/platform.dart';
    import 'package:sqflite_common_ffi/sqflite_ffi.dart';
    

    Future<void> initDatabaseFactory() async {
      final native = Platform.current.nativePlatform;
    

      if (native != null && (native.isWindows || native.isLinux)) {
        // Windows and Linux have no built-in sqflite support, so use FFI
        sqfliteFfiInit();
        databaseFactory = databaseFactoryFfi;
      }
      // Android, iOS and macOS keep the default sqflite factory.
    }

    The rest of the app only ever calls initDatabaseFactory(). It never needs to know which platform it is on.

2.2 Save and Load the Preference

The root of the app needs to be a StatefulWidget, because changing the theme changes the state of the whole MaterialApp. Replace main.dart:

x
    import 'package:flutter/material.dart';
    import 'package:shared_preferences/shared_preferences.dart';
    import 'views/theme_selection_page.dart';


    void main() async {
      // Required because we use a plugin (SharedPreferences) before runApp
      WidgetsFlutterBinding.ensureInitialized();


      final prefs = await SharedPreferences.getInstance();
      // Read the saved value. It is null if nothing has been saved yet.
      final String? savedMode = prefs.getString('themeMode');


      runApp(MyApp(savedMode: savedMode));
    }


    class MyApp extends StatefulWidget {
      final String? savedMode;


      const MyApp({super.key, this.savedMode});


      @override
      State<MyApp> createState() => _MyAppState();
    }


    class _MyAppState extends State<MyApp> {
      late ThemeMode _themeMode;


      @override
      void initState() {
        super.initState();
        // If nothing was saved (null), default to light mode
        _themeMode = (widget.savedMode ?? 'light') == 'dark'
            ? ThemeMode.dark
            : ThemeMode.light;
      }


      Future<void> _setTheme(ThemeMode mode) async {
        final prefs = await SharedPreferences.getInstance();
        await prefs.setString('themeMode', mode == ThemeMode.dark ? 'dark' : 'light');


        setState(() => _themeMode = mode);
      }


      Future<void> _resetTheme() async {
        final prefs = await SharedPreferences.getInstance();
        await prefs.remove('themeMode');


        setState(() => _themeMode = ThemeMode.light);
      }


      @override
      Widget build(BuildContext context) {
        return MaterialApp(
          title: 'Data Notebook',
          debugShowCheckedModeBanner: false,
          theme: ThemeData(
            colorScheme: ColorScheme.fromSeed(seedColor: Colors.teal),
            useMaterial3: true,
          ),
          darkTheme: ThemeData(
            colorScheme: ColorScheme.fromSeed(
              seedColor: Colors.teal,
              brightness: Brightness.dark,
            ),
            useMaterial3: true,
          ),

Activity 4 – Build the Data Model

The next part of the app needs to store more complex data: a list of items, each with a title and a description. That is not a job for SharedPreferences. We need a database.

Note

We've looked at data models before in the networking lab. A model represents the structure of the data. For each entity we define a corresponding class, and each entity corresponds to a table in the database. The model follows the same properties and structure as the database table.

4.1 The DataItem Model

Create lib/models/data_item.dart:

x
class DataItem {
  final int? id; // null until the database has given the item an id
  final String title;
  final String desc;


  // Model constructor (to create the model)
  DataItem({this.id, required this.title, required this.desc});


  // Create a DataItem from a Map (a key/value pair returned by the database).
  // The keys must match the column names in the table.
  factory DataItem.fromMap(Map<String, dynamic> map) {
    return DataItem(
      id: map['data_id'],
      title: map['data_title'],
      desc: map['data_desc'],
    );
  }


  // Convert a DataItem into a Map.
  // The keys must correspond to the names of the columns in the database.
  Map<String, dynamic> toMap() {
    return {
      'data_id': id,
      'data_title': title,
      'data_desc': desc,
    };
  }


  @override
  String toString() {
    return 'DataItem($id -> $title: $desc)';
  }
}

Activity 5 – Build the Database Helper

The Database Helper organises all database functionality in one centralised file. It:

  • Implements the singleton pattern, which ensures only one instance of the database exists at a time (better resource management).

  • Defines the common CRUD (Create, Retrieve, Update, Delete) functions.

Note

The singleton pattern is used in object-oriented programming to make sure a class has only one instance and provides a global point of access to it. Think about why opening the same database many times in an app would be a problem.

5.1 Create the Database and Table

Create lib/database/database_helper.dart. We will add to this file during the activity. Start with the singleton and the table creation:

x
import 'package:path/path.dart';
import 'package:sqflite/sqflite.dart';
import '../models/data_item.dart';


class DatabaseHelper {
  static const _databaseName = 'notebook_database.db'; // database file name
  static const _databaseVersion = 1; // database version


  // Table and column names
  static const table = 'tbl_data';
  static const columnId = 'data_id';
  static const columnTitle = 'data_title';
  static const columnDesc = 'data_desc';


  // Make this a singleton class
  DatabaseHelper._privateConstructor();
  static final DatabaseHelper instance = DatabaseHelper._privateConstructor();


  // Only have a single app-wide reference to the database
  static Database? _database;


  Future<Database> get database async {
    if (_database != null) return _database!;
    // lazily instantiate the db the first time it is accessed
    _database = await _initDatabase();
    return _database!;
  }


  // This opens the database (and creates it if it doesn't exist)
  Future<Database> _initDatabase() async {
    final dbFolder = await getDatabasesPath();
    final path = join(dbFolder, _databaseName);
    return await openDatabase(
      path,
      version: _databaseVersion,
      onCreate: _onCreate,
    );
  }


  // SQL code to create the database table
  Future _onCreate(Database db, int version) async {
    await db.execute('''
      CREATE TABLE $table (
        $columnId INTEGER PRIMARY KEY AUTOINCREMENT,
        $columnTitle TEXT NOT NULL,
        $columnDesc TEXT NOT NULL
      )
    ''');
  }


  // ... the CRUD methods go below
}

Note

The lecture slides use getApplicationDocumentsDirectory() from the path_provider package to find where to store the file. getDatabasesPath() (part of sqflite) gives you the default location for databases, so no extra package is needed.

5.2 Create (Insert)

Add the following methods inside the DatabaseHelper class:

x
  // Inserts a DataItem as a new row. The return value is the id of the inserted row.
  Future<int> insert(DataItem item) async {
    final db = await instance.database;
    return await db.insert(table, item.toMap());
  }

5.3 Read (Query)

x
  // Returns every row as a list of DataItem objects (newest first).
  Future<List<DataItem>> queryAllRows() async {
    final db = await instance.database;
    final List<Map<String, dynamic>> maps =
        await db.query(table, orderBy: '$columnId DESC');


    // Convert the List<Map<String, dynamic>> into a List<DataItem>.
    return List.generate(maps.length, (i) => DataItem.fromMap(maps[i]));
  }


  // Returns a single DataItem using its id in the WHERE clause, or null if none exists.
  Future<DataItem?> queryById(int id) async {
    final db = await instance.database;
    final maps = await db.query(
      table,
      where: '$columnId = ?',
      whereArgs: [id],
    );
    if (maps.isEmpty) return null;
    return DataItem.fromMap(maps.first);
  }


  // All of the methods (insert, query, update, delete) can also be done using
  // raw SQL commands. This method uses a raw query to give the row count.
  Future<int> queryRowCount() async {
    final db = await instance.database;
    return Sqflite.firstIntValue(
          await db.rawQuery('SELECT COUNT(*) FROM $table'),
        ) ??
        0;
  }

5.4 Update

x
  // Updates the row with the matching id. The number of affected rows is returned.
  Future<int> update(DataItem item) async {
    final db = await instance.database;
    return await db.update(
      table,
      item.toMap(),
      where: '$columnId = ?',
      whereArgs: [item.id],
    );
  }

5.5 Delete and Debugging Helpers

x
  // Deletes the row with the specified id. The number of affected rows is returned.
  Future<int> delete(int id) async {
    final db = await instance.database;
    return await db.delete(table, where: '$columnId = ?', whereArgs: [id]);
  }


  // Deletes ALL rows. Useful for testing and debugging.
  Future<int> clearTable() async {
    final db = await instance.database;
    return await db.delete(table);
  }

Important

Always use where with whereArgs and the ? placeholder, rather than building the SQL string yourself with $id. Passing values separately prevents SQL injection.

Activity 9 – Advanced: Add a Colour and Update the Schema

9.1 Update the Model

Update the DataItem model to include a colour property that changes the background colour of each list item. SQLite cannot store a Color directly, so we store it as an integer.

In data_item.dart:

x
import 'package:flutter/material.dart';


class DataItem {
  final int? id;
  final String title;
  final String desc;
  final int colour; // ARGB value stored as an integer


  DataItem({
    this.id,
    required this.title,
    required this.desc,
    this.colour = 0xFF9E9E9E, // default grey
  });


  Color get colourValue => Color(colour);


  factory DataItem.fromMap(Map<String, dynamic> map) {
    return DataItem(
      id: map['data_id'],
      title: map['data_title'],
      desc: map['data_desc'],
      colour: map['data_colour'],
    );
  }


  Map<String, dynamic> toMap() {
    return {
      'data_id': id,
      'data_title': title,
      'data_desc': desc,
      'data_colour': colour,
    };
  }


  @override
  String toString() => 'DataItem($id -> $title: $desc, colour: $colour)';
}

9.2 Update the Database (Migration)

You've changed the structure of the table, but the existing database on your device still has the old structure. If you just ran the app, data_colour would not exist and the app would crash.

This is what the _databaseVersion is for. Increase it and provide an onUpgrade callback in database_helper.dart:

x
static const _databaseVersion = 2; // was 1
static const columnColour = 'data_colour';
x
return await openDatabase(
  path,
  version: _databaseVersion,
  onCreate: _onCreate,
  onUpgrade: _onUpgrade,
);

Update _onCreate to include the new column, and add _onUpgrade:

x
Future _onCreate(Database db, int version) async {
  await db.execute('''
    CREATE TABLE $table (
      $columnId INTEGER PRIMARY KEY AUTOINCREMENT,
      $columnTitle TEXT NOT NULL,
      $columnDesc TEXT NOT NULL,
      $columnColour INTEGER NOT NULL DEFAULT 4288585374
    )
  ''');
}


// Called when an existing database has an older version than the one requested
Future _onUpgrade(Database db, int oldVersion, int newVersion) async {
  if (oldVersion < 2) {
    // 4288585374 is 0xFF9E9E9E (grey) as a decimal number
    await db.execute(
      'ALTER TABLE $table ADD COLUMN $columnColour INTEGER NOT NULL DEFAULT 4288585374',
    );
  }
}
