Introduction

Mobile applications rarely work in isolation. Whether it is loading a news feed, signing in with an existing account or saving a score, most applications need to communicate with a server over the Internet. These requests take time, and the length of that time is not under the control of the application: it depends on the network, the server and the amount of data being requested.

Dart is a single-threaded language. If your application simply waited for a slow request to finish, all other code would be frozen, including the code that draws the screen and responds to the user's taps. To the user, the application would appear to have crashed. This is where asynchronous programming is used. Instead of waiting, the application starts the request, carries on with other work, and is notified when the result is ready.

In this lab you will build an application that retrieves data from a web API without freezing the user interface. You will begin with a simple Future, replace it with a real API call, process the JSON that is returned, and finally present the data to the user as a list of profiles.

The lab is structured so that each activity builds upon the previous one. By the end of the session you will have built an application that follows the same pattern used by many real-world applications: make a request, wait for the data, handle problems, and display the result.

1.2 A Simulated Asynchronous Call

A Future represents a value that will be available later. Before using a real server, we will simulate a slow call using Future.delayed().

Type the following into lib/main.dart (do not copy and paste, as typing helps you learn the syntax):

xxxxxxxxxx
import 'package:flutter/material.dart';


void main() {
  runApp(const MyApp());
}


class MyApp extends StatelessWidget {
  const MyApp({super.key});


  // Simulates a slow call by waiting for 2 seconds
  Future<String> fetchData() async {
    await Future.delayed(const Duration(seconds: 2));
    return "Data loaded";
  }


  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text("Futures")),
        body: Center(
          child: FutureBuilder<String>(
            future: fetchData(),
            builder: (context, snapshot) {


              if (snapshot.connectionState == ConnectionState.waiting) {
                return const CircularProgressIndicator();
              } else if (snapshot.hasError) {
                return Text("Error: ${snapshot.error}");
              } else {
                return Text(snapshot.data ?? "");
              }


            },
          ),
        ),
      ),
    );
  }
}

Run the application.

Activity 2 – APIs and Packages

2.1 Understanding APIs

It is not uncommon for mobile applications to make an HTTP request. This exchange of information is how mobile applications communicate to retrieve and send data. In this activity, you will retrieve information from a server. The application calls an endpoint (a URL) on the Internet and receives data in return. The data often originates from another source, such as a database, and is returned to the mobile application by a RESTful call, but it could also come from an external service.

An Application Programming Interface (API) is a process that a server runs to read and write data in a controlled way. This allows the server to decide what a call can retrieve, how it is retrieved and who can access it. Access is usually controlled by providing a token (a key that identifies your application or user) with each request. Tokens are preferred over sending a username and password with every request, which is not secure. The server checks the token and decides whether to grant access to the data.

For example, third-party developers can build apps that use Facebook's infrastructure. An app might use Facebook to handle sign-in, so it doesn't need its own account system, password resets and so on. The user grants permission, and the app receives a token. The app can then make API calls on the user's behalf, such as posting a message when they unlock something.

For now, all you need to understand is that third-party applications can retrieve and store data using API calls.

2.2 Packages

Including libraries in your Flutter application is a great way to extend its functionality by reusing code that other developers have created. There are four stages to adding a package to your application:

  1. Find the package you want to use at pub.dev.

  2. Add it to the pubspec.yaml file.

  3. Import the package into the Dart file that needs it.

  4. Use it within your code.

Be careful when selecting a package. pub.dev shows which platforms each package supports (Android, iOS, Web and so on). Some packages won't support the platform you are targeting.

Each package should have a README that explains how to import and use it.

Activity 3 – Making an API Call

3.1 Replace the Simulated Call

You will now replace the simulated call with a real request to an API. The API endpoint is:

xxxxxxxxxx
https://dummyapi.io/data/v1/user

Add the following imports at the top of main.dart:

xxxxxxxxxx
import 'dart:convert';
import 'package:http/http.dart' as http;

Replace the fetchData function with:

xxxxxxxxxx
Future<String> fetchData() async {


  final queryParameters = {
    'limit': '10',
  };


  final uri = Uri.https('dummyapi.io', '/data/v1/user', queryParameters);


  final response = await http.get(
    uri,
    headers: {'app-id': '61c32172b78391f6b89599eb'},
  );


  print(response.statusCode);


  final responseJson = jsonDecode(response.body);


  String returnedData = "";


  responseJson['data'].forEach((element) {
    returnedData += element["id"];
    print(element["id"]);
  });


  return returnedData;


}

Save and run the application.
