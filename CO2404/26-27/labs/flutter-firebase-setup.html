Introduction

In the previous lab you stored data locally on the device using SharedPreferences and SQLite. That is excellent for settings and offline use, but the data lives on one device only. If the user installs your app on a second phone, or you want two users to see the same data, you need a cloud backend.

Firebase is a platform from Google that provides ready-made backend services, so you don't have to build and host your own server. The services you will meet most often are:

Each product has its own Flutter plugin, and every plugin depends on one core plugin, firebase_core, which connects your app to your Firebase project.

Note

Firebase's data model is different from SQLite. SQLite stores rows in tables with a fixed schema. Cloud Firestore is a NoSQL database that stores documents (similar to JSON objects) inside collections. You should be familiar with this from the material covered in the lectures.

  1. Install the tools.

  2. Create a Firebase project.

  3. Connect a new Flutter app to the project.

  4. Prove the connection works by saving a message to the cloud and reading it back.

Activities

Activity 1 – Install the Command Line Tools

You will need a Google account that you can sign in to the Firebase console.

Two command line tools do the connecting for us:

  • The Firebase CLI (firebase) lets you sign in to Firebase and manage projects from the terminal.

  • The FlutterFire CLI (flutterfire) reads your Flutter project and registers each of its platforms with Firebase.

1.1 Install the Firebase CLI

Follow the instructions at firebase.google.com/docs/cli for your operating system. Then check it installed:

x
firebase --version

1.2 Sign in

Sign in with your Google account:

x
firebase login

A browser window opens. Choose your Google account and allow access. When the terminal confirms you are logged in, check it:

x
firebase projects:list

This lists the Firebase projects your account can see (it may be empty).

1.3 Install the FlutterFire CLI

You can run this from any directory:

x
dart pub global activate flutterfire_cli

Then check it works:

x
flutterfire --version

Important

If your terminal says flutterfire: command not found, the folder where Dart installs global tools isn't on your PATH. Dart usually prints a warning telling you which folder to add at the end of the activate command. Typically this is ~/.pub-cache/bin on macOS and Linux, and %LOCALAPPDATA%\Pub\Cache\bin on Windows. Add it to your PATH, then open a new terminal window and try again.

Checkpoint

  1. What is the difference between firebase and flutterfire?

  2. What does firebase projects:list show, and why is it useful for checking your login?

  3. Why do we install flutterfire_cli with dart pub global activate rather than adding it to pubspec.yaml?

Activity 3 – Connect Your App with flutterfire configure

3.1 Run the Configuration

In your terminal, from inside the firebase_setup project folder, run:

x
flutterfire configure

The tool asks you a series of questions:

  1. Select a Firebase project. Choose co2404-firebase-setup project you created in Activity 2.

  2. Select the platforms your app supports (Android, iOS, web, and so on). Use the arrow keys and space bar. Select only the ones you will test on today.

  3. It then registers each selected platform as a separate app inside your Firebase project, and writes the connection details to your project.

3.2 What Has Changed?

Look at your Flutter project. A new file has appeared:

xxxxxxxxxx
lib/
├── main.dart
└── firebase_options.dart    <- generated by flutterfire configure

Open firebase_options.dart. It contains a DefaultFirebaseOptions class with a currentPlatform getter that returns the correct set of options (android, ios, web etc.) for whichever platform the app is running on.

Now look in the Firebase console. Open Project settings (the cog icon) and scroll to Your apps. You should see an app for each platform you selected.

Checkpoint

  1. What file did flutterfire configure create, and where?

  2. Find the projectId in firebase_options.dart. Does it match the project ID you noted in Activity 3?

  3. The values in firebase_options.dart are unique to your project, but Firebase describes them as non-secret identifiers. They tell the SDK which project to talk to. What actually protects your data from other people? (Hint: look up Firebase Security Rules and App Check. You will use them in later labs.)

Note

You will need to run flutterfire configure again whenever you start supporting a new platform or start using a new Firebase product. Re-running it keeps the configuration up to date and, for Android, adds any Gradle plugins that those products need.

Activity 4 – Initialise Firebase in Your App

4.1 Install the Core Plugin

Every Firebase plugin depends on firebase_core. Add it:

x
flutter pub add firebase_core

Open pubspec.yaml and confirm it appears under dependencies, at the same level as flutter:

xxxxxxxxxx
dependencies:
  flutter:
    sdk: flutter
  firebase_core: ^4.0.0

Tip

The version number you see will be newer. That's fine, always use the latest version. If you edit pubspec.yaml by hand, run flutter pub get afterwards.

Run the configuration again so the project is up to date with the newly added plugin:

x
flutterfire configure

4.2 Initialise Firebase

Add the flutter_web_pluginsto your pubspec.yaml it should look like this:

xxxxxxxxxx
 flutter:
    sdk: flutter
  flutter_web_plugins:
    sdk: flutter
  cupertino_icons: ^1.0.8
  firebase_core: ^5.0.0
  cloud_firestore: ^7.1.0

Replace the contents of lib/main.dart with the following. It initialises Firebase before the app starts and shows a page that proves it connected:

x
import 'package:firebase_core/firebase_core.dart';
import 'package:cloud_firestore/cloud_firestore.dart';
import 'package:flutter/material.dart';
import 'package:flutter/foundation.dart' show kIsWeb;
import 'firebase_options.dart';


Future<void> main() async {
  // Required because we use a plugin before runApp
  WidgetsFlutterBinding.ensureInitialized();


  // Connect to the Firebase project described in firebase_options.dart
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );


 final db = FirebaseFirestore.instanceFor(
    app: Firebase.app(),
    databaseId: 'co2404-demo',
  );


  // FORCE LONG POLLING FOR WEB (Bypasses firewall/WebSocket blocks)
  if (kIsWeb) {
    db.settings = const Settings(
      persistenceEnabled: false,
      webExperimentalAutoDetectLongPolling:
          true, // disable offline persistence cache issues on web if needed
    );
  }
  runApp(const FirebaseSetupApp());
}


class FirebaseSetupApp extends StatelessWidget {
  const FirebaseSetupApp({super.key});


  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Firebase Setup',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange),
        useMaterial3: true,
      ),
      home: const StatusPage(),
    );
  }
}

  const StatusPage({super.key});

Important

Test mode allows anybody who knows your project to read and write your data, and it is intended to be switched off after a short time. That is acceptable for a lab with no real data. It is not acceptable for an application with real users. You will write proper Security Rules in a later lab. If you get a permission-denied error later, it usually means the test-mode rules have expired or the rules are locked.

5.2 Write and Read a Document

Replace the StatusPage class in main.dart with a StatefulWidget that writes a message to Firestore and shows the latest ten messages. 

x
class StatusPage extends StatefulWidget {
  const StatusPage({super.key});


  @override
  State<StatusPage> createState() => _StatusPageState();
}


class _StatusPageState extends State<StatusPage> {
  // A collection is a group of documents (similar to a table in SQLite)
   final CollectionReference<Map<String, dynamic>> _tests =
      FirebaseFirestore.instanceFor(
        app: Firebase.app(),
        databaseId: 'co2404-demo',
      ).collection('connection_tests');


  Future<void> _writeTest() async {
    try {
      await _tests.add({
        'message': 'Hello from Flutter',
        'platform': kIsWeb ? 'web' : defaultTargetPlatform.name,
        // The server fills in the time, so it is the same on every device
        'createdAt': FieldValue.serverTimestamp(),
      });
    } catch (e) {
      debugPrint('Write failed: $e');
      if (!mounted) return;
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text('Write failed: $e')),
      );
    }
  }


  @override
  Widget build(BuildContext context) {
    final app = Firebase.app();


    return Scaffold(
      appBar: AppBar(title: const Text('Firebase Setup')),
      body: Column(
        children: [
          const SizedBox(height: 16),
          const Icon(Icons.cloud_done, size: 64, color: Colors.green),
          Text('Project ID: ${app.options.projectId}'),
          const SizedBox(height: 16),
          ElevatedButton.icon(
            onPressed: _writeTest,
            icon: const Icon(Icons.cloud_upload),
            label: const Text('Write test document'),
          ),
          const SizedBox(height: 16),
          Expanded(
            // snapshots() is a Stream: the list updates whenever the data changes
            child: StreamBuilder<QuerySnapshot<Map<String, dynamic>>>(
              stream: _tests
                  .orderBy('createdAt', descending: true)
                  .limit(10)
                  .snapshots(),
              builder: (context, snapshot) {
                if (snapshot.hasError) {
                  return Center(child: Text('Error: ${snapshot.error}'));
                }
                if (!snapshot.hasData) {
                  return const Center(child: CircularProgressIndicator());
                }


                final docs = snapshot.data!.docs;
                if (docs.isEmpty) {
                  return const Center(child: Text('No documents yet'));
                }


                return ListView.builder(
                  itemCount: docs.length,
                  itemBuilder: (context, index) {
                    final data = docs[index].data();
                    // createdAt is briefly null until the server confirms the write
                    final created = (data['createdAt'] as Timestamp?)?.toDate();
                    return Card(
                      margin: const EdgeInsets.symmetric(horizontal: 12, vertical: 6),
                      child: ListTile(
                        leading: const Icon(Icons.message),
                        title: Text(data['message'] ?? ''),
                        subtitle: Text(
                          'From ${data['platform']}'
                          '${created != null ? ' at $created' : ''}',
                        ),
                      ),
                    );
                  },
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}

5.3 Test It

  1. Do a full rebuild with flutter run.

  2. Press Write test document a few times. New cards should appear almost instantly.

  3. In the Firebase console, open Firestore Database → Data. You should see a connection_tests collection containing the documents you created.

  4. In the console, click Add document (or edit a field of an existing document) and watch your app. Does it update without you doing anything?

    1. If you are adding a new document use the same fields as your code generates createdAt, message and platform

      Note

      Your view is looking for a timestamp for createdAt so make sure you set this in the database

      You should then see the item appear in your view (this a streaming the data directly from the datbase)

  5. If you can, run the app on a second platform (e.g. Chrome and an emulator) at the same time, then write from one. Does the other update?

Checkpoint

  1. Which part of the code writes data? Which part reads it?

  2. What is the difference between a collection and a document? How does that compare with a table and a row in SQLite?

  3. The list updates without any setState(). Why? (Hint: what is a Stream, and what does StreamBuilder do?)

  4. Why is it only retrieving 10 items from the database?

  5. Why is the timestamp created by the server (FieldValue.serverTimestamp()) rather than DateTime.now() on the device?

  6. Turn off the Wi-Fi on your emulator and press the write button. What happens to the card? What happens when you turn the connection back on?
