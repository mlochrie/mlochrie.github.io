Introduction

In the lecture we looked at why real-world applications rely on data from external sources such as APIs. That data usually arrives as JSON, which is just text. On its own it is awkward to work with: there is no type safety, a mistyped key only fails at runtime, and your UI code ends up full of json['firstName'] lookups.

A data model solves this. It acts as a blueprint (or a mould) that shapes raw data into something usable in your app. A model:

  • Represents the structure of the data (e.g. a User, Post or Event).

  • Provides methods to convert between JSON and Dart objects.

  • Helps maintain type safety, readability and data integrity.

In this lab you will build a User Directory application. You will first inspect a live API using Postman, then build the model, service and view layers one at a time. Each activity builds upon the previous one.

By the end of the session your application will:

  • Request a list of users from a REST API.

  • Parse the JSON response into Dart objects.

  • Present the users in a scrolling list of cards with their picture and name.

  • Show a progress indicator while it loads.

  • Show an error message if the request fails.

Activity 1 – Debugging an API with Postman

When you build applications that parse HTTP data you need to think about where errors might occur. Of course you might have errors in your code when parsing objects, but you now might also have errors on the server (backend). Debugging both at once is difficult. It is best practice to test the API in another tool first, so you know whether the problem is in the API or in your Flutter code.

Postman lets you create and save HTTP requests and responses, set up your connections, input your test criteria, debug the response and save it for later.

Before you continue: make sure you have downloaded Postman for your chosen operating system: Windows x64, Windows x32, macOS, Linux or Web.

Further Reading

Dart is a single-threaded language, so Flutter apps can only do one thing at once. However, this doesn't mean the app has to wait until a slow task finishes. Network calls are slow, so Dart returns a Future: a promise that the data will arrive later. You can respond to it with .then(), or more simply with await inside an async function. Revisit https://dart.dev/codelabs/async-await if you need to. You will need to demonstrate both reading/writing a file and handling HTTP GET/POST requests in your assessment.

Activity 3 – Build the Data Model

A model represents the structure of your data and knows how to convert between JSON and Dart objects:

  • Deserialisation: converting JSON into a Dart object (fromJson).

  • Serialisation: converting a Dart object back into JSON (toJson).

Note

There are packages such as json_serializable that generate this code for you. In this module we are going to do the process manually so you understand what is happening.

3.1 The User Model

Create lib/models/user.dart:

x
class User {
  final String id;
  final String title;
  final String firstName;
  final String lastName;
  final String picture;


  // Named constructor with required fields
  User({
    required this.id,
    required this.title,
    required this.firstName,
    required this.lastName,
    required this.picture,
  });


  // Factory constructor to create a User object from a JSON map.
  // json['firstName'] extracts the value stored against that key.
  factory User.fromJson(Map<String, dynamic> json) {
    return User(
      id: json['id'],
      title: json['title'] ?? '',
      firstName: json['firstName'],
      lastName: json['lastName'],
      picture: json['picture'] ?? '',
    );
  }


  // Converts the User object back into a JSON-compatible map.
  Map<String, dynamic> toJson() {
    return {
      'id': id,
      'title': title,
      'firstName': firstName,
      'lastName': lastName,
      'picture': picture,
    };
  }


  // A convenience getter used by the UI.
  String get fullName => '$firstName $lastName';
}

Important

The strings in json['...'] must match the keys in the API exactly, including capitalisation. json['firstname'] will not find firstName. A typo here is one of the most common causes of runtime errors. Compare your keys with the Postman response.

3.2 The Response Model

The API does not return a list of users on its own. It returns an object that contains the list, plus paging information. The full response needs its own class. In the lecture this was the Astros class wrapping a list of Astronaut objects.

Create lib/models/user_response.dart:

x
import 'user.dart';


class UserResponse {
  final List<User> data;
  final int total;
  final int page;
  final int limit;


  UserResponse({
    required this.data,
    required this.total,
    required this.page,
    required this.limit,
  });


  factory UserResponse.fromJson(Map<String, dynamic> json) {
    return UserResponse(
      // json['data'] is a list, so convert each item using User.fromJson
      data: (json['data'] as List)
          .map((item) => User.fromJson(item))
          .toList(),
      total: json['total'],
      page: json['page'],
      limit: json['limit'],
    );
  }


  Map<String, dynamic> toJson() {
    return {
      'data': data.map((user) => user.toJson()).toList(),
      'total': total,
      'page': page,
      'limit': limit,
    };
  }
}

Activity 4 – Build the Service Layer

The service layer fetches data from the API and converts it into models. Your UI should not need to know how the data is fetched, only that it gets a list of User objects.

4.1 Create the Service

Create lib/services/user_service.dart:

x
import 'dart:convert';
import 'package:http/http.dart' as http;
import '../models/user.dart';
import '../models/user_response.dart';


class UserService {
  static const String _baseUrl = 'https://dummyapi.io/data/v1';
  static const String _appId = '61c32172b78391f6b89599eb';


  Future<List<User>> fetchUsers({int limit = 10}) async {
    final response = await http.get(
      Uri.parse('$_baseUrl/user?limit=$limit'),
      headers: {'app-id': _appId},
    );


    // Anything other than 200 (OK) means something went wrong.
    if (response.statusCode != 200) {
      throw Exception('Failed to load users (${response.statusCode})');
    }


    return UserResponse.fromJson(jsonDecode(response.body)).data;
  }
}

Activity 5 – Present the Data with a FutureBuilder

Now we build the view layer. A FutureBuilder waits for a Future to complete and rebuilds the UI depending on its state: while we wait we show a progress indicator, and when the data arrives we show a list.

5.1 Create the Page

Create lib/views/user_list_page.dart:

x
import 'package:flutter/material.dart';
import '../models/user.dart';
import '../services/user_service.dart';


class UserListPage extends StatefulWidget {
  const UserListPage({super.key});


  @override
  State<UserListPage> createState() => _UserListPageState();
}


class _UserListPageState extends State<UserListPage> {
  final UserService _service = UserService();
  late Future<List<User>> _usersFuture;


  @override
  void initState() {
    super.initState();
    _usersFuture = _service.fetchUsers(limit: 10);
  }


  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('User Directory')),
      body: FutureBuilder<List<User>>(
        future: _usersFuture,
        builder: (BuildContext context, AsyncSnapshot<List<User>> snapshot) {
          if (snapshot.connectionState != ConnectionState.done) {
            return const Center(child: CircularProgressIndicator());
          } else {
            return ListView(
              children: snapshot.data!
                  .map((u) => ListTile(
                        title: Text(u.fullName),
                        subtitle: Text(u.title),
                      ))
                  .toList(),
            );
          }
        },
      ),
    );
  }
}

Activity 7 – Adding a Button and Progress Indicator

At the moment the data loads as soon as the page opens. In many apps the user decides when to fetch data (e.g. pull-to-refresh or a Search button). We will swap the FutureBuilder for a version where we manage the state.

7.1 Manage State Manually

Replace _UserListPageState in user_list_page.dart with the following:

x
class _UserListPageState extends State<UserListPage> {
  final UserService _service = UserService();


  List<User> _users = [];
  bool _connecting = false;


  Future<void> _loadUsers() async {
    // trigger the progress indicator ...
    setState(() => _connecting = true);


    final users = await _service.fetchUsers(limit: 10);


    setState(() {
      // set the users to show in the UI
      _users = users;
      // remove the progress indicator ...
      _connecting = false;
    });
  }


  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('User Directory')),
      body: Column(
        children: [
          const SizedBox(height: 10),
          // Show progress indicator while connecting,
          // show the elevated button when not connecting
          _connecting
              ? const CircularProgressIndicator()
              : ElevatedButton(
                  onPressed: () => _loadUsers(),
                  child: const Text('Load users'),
                ),
          const SizedBox(height: 10),
          Expanded(
            child: ListView.builder(
              itemCount: _users.length,
              itemBuilder: (context, index) => UserCard(user: _users[index]),
            ),
          ),
        ],
      ),
    );
  }
}

8.2 Use try/catch

Add an _error variable and update _loadUsers():

x
bool _error = false;


Future<void> _loadUsers() async {
  // trigger the progress indicator and clear any previous error
  setState(() {
    _connecting = true;
    _error = false;
  });


  try {
    final users = await _service.fetchUsers(limit: 10);


    setState(() {
      // if here, it completed without error
      _users = users;
      _connecting = false;
    });
  } catch (e) {
    debugPrint('Request failed: $e');
    setState(() {
      // mark the error
      _error = true;
      // remove the progress indicator ...
      _connecting = false;
    });
  }
}

Note

The lecture used on Exception. A mistyped key in fromJson throws a TypeError, which is an Error rather than an Exception, so on Exception would not catch it. Using a plain catch (e) with debugPrint is useful while developing, because you can see what went wrong.
